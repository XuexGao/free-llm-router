/* ═══════════════════════════════════════════════════════════════════
   移动端适配（用户报障：手机上界面超出屏幕、文字换行错乱）

   ## 三个真实成因（逐条对应下面的规则）

   1. **表格是「不可收缩」的**：`table { width: 100% }` 只保证「尽量 100%」，
      但单元格内容（长 uid、长模型名、长原因）会把表撑宽 —— 因为默认
      `table-layout: auto` 会按内容计算最小宽度。手机上必然横向溢出。
   2. **固定宽度元素**：`.bar-label`（78px）、`.bar-val`（60px）、
      `.model-row .mname`（150px）在小屏上占比过大，把中间内容挤到换行。
   3. **长串不换行**：uid / token / URL 这类无空格长串不会自动断行，
      会直接顶破容器。

   ⚠️ 断行只用 `overflow-wrap: anywhere`（配合 `word-break: break-word`），
   **不用** `word-break: break-all` —— 后者会把正常英文单词也拦腰截断，
   中文界面里读起来很难受。
   ═══════════════════════════════════════════════════════════════════ */

/* 长串（uid / URL / token）必须能在任意位置断行，否则顶破容器 */
.uid, .out, td, th, .hint, .card strong, .model-row .mname {
  overflow-wrap: anywhere;
  word-break: break-word;
}

/* 表格：允许横向滚动而不是撑破页面（手机上的标准做法） */
.table-wrap { overflow-x: auto; -webkit-overflow-scrolling: touch; }
table { table-layout: auto; }
/*
 * ⚠️ 表格必须按内容取宽，否则 .table-wrap 的横向滚动**永远不会触发**。
 *
 * 根因（线上实测，P1）：全局的 `table { width: 100% }` 让表格永远塞满容器、
 * 永不溢出，于是 `overflow-x: auto` 形同虚设 —— 表格不是「滚动」，而是
 * **被压缩**。代价在手机上很直观：五列明细表（冷却中 / 模型限流）的表头被
 * 挤成竖排单字（「类/型」「原/因」），供应商名 `codearts` 断成 `codea/rts`。
 * 实测对照：原样式下 表格宽 309px == 容器 309px（不滚动）；
 *          `width: max-content` 下 表格宽 397px > 容器 340px（真正可滚动）。
 * `min-width: 100%` 保证窄表（如「配置」两列）仍占满容器，不会缩成一小块。
 */
.table-wrap > table { width: max-content; min-width: 100%; }

/*
 * ⚠️ 必须允许网格项收缩，否则上面那条规则反而会把**整个页面**顶宽。
 *
 * `main` 是 `display: grid`，而网格项默认 `min-width: auto` —— 也就是
 * 「不小于内容的最小宽度」。表格一旦按 max-content 取宽，这个最小值就跟着
 * 变大，网格轨道被撑开、页面横向溢出。
 *
 * 实测（390px 视口，用量视图）：加 `min-width: 0` 前
 *   docScrollW 422 > 视口 375（溢出 47px），.table-wrap 自己被撑到 376px、
 *   横向滚动依旧不触发；加上之后 section 回到 351px、wrap 317px、
 *   表格 335px → **真正在容器内滚动**，页面溢出归零。
 *
 * 这与 `.count { min-width: 0 }` 是同一类陷阱（flex/grid 项默认不收缩）。
 * 用 `main > *` 覆盖所有网格项（含 WAF 横幅），将来新增区块也不会再踩。
 */
main > * { min-width: 0; }
